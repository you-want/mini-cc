# AI 的记忆和安全，我踩过的坑

> 让 AI 越来越聪明的同时，别让它把你的电脑搞崩了

---

做 AI Agent 有两个绕不开的问题：
1. 怎么让它**记住东西**（跨会话的记忆）
2. 怎么**不让它乱来**（安全拦截）

这两个话题看似不相关，但在实际开发中它们经常交叉出现——比如 AI 记住了"用户喜欢用 `rm -rf` 清理文件"，下次它就主动帮你删了。

---

## 记忆系统：比想象中简单，比想象中有效

我没有搞什么向量数据库、embedding 检索，就是**一个纯文本文件**。

```
.ai_memory/
└── global_memory.txt    ← 所有持久化记忆都存在这里
```

为什么不存 JSON？因为我发现对于"项目规则和约定"这种记忆，纯文本比结构化数据更好用——LLM 直接读纯文本就能理解，不需要反序列化的开销。

### MemoryManager

```python
class MemoryManager:
    def __init__(self, workspace_dir="."):
        self.memory_dir = Path(workspace_dir) / ".ai_memory"
        self.global_memory_file = self.memory_dir / "global_memory.txt"
        self._ensure_memory_dir()
    
    def get_global_memory(self) -> str:
        """读取全局记忆，注入到 System Prompt"""
        if not self.global_memory_file.exists():
            return ""
        content = self.global_memory_file.read_text(encoding="utf-8")
        # 防爆截断：超过 5000 字符就截断
        if len(content) > 5000:
            content = "...(记忆过长被截断)...\n" + content[-5000:]
        return content
    
    def add_memory(self, memory_text: str) -> None:
        """追加一条新记忆"""
        timestamp = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
        with open(self.global_memory_file, "a", encoding="utf-8") as f:
            f.write(f"\n[{timestamp}] {memory_text}")
```

就这么简单。读文件、追加写、超长截断。

### 记忆怎么注入 LLM

在 CLI 启动时，把全局记忆追加到 System Prompt 里：

```python
memory_manager = MemoryManager()
global_memory = memory_manager.get_global_memory()

if global_memory:
    # 直接拼到系统提示词的末尾
    first_msg = provider.messages[0]
    first_msg["content"] += f"\n\n=== 项目全局记忆 ===\n{global_memory}\n===================="
```

LLM 每次启动都能看到这些记忆，就像你给新同事交接文档一样。

### 让 AI 主动记东西

最有意思的是 `AddMemoryTool`——让 AI 自己决定什么时候该记东西：

```python
class AddMemoryTool(BaseTool):
    name = "AddMemory"
    description = (
        "将重要的项目规则或约定永久写入 .ai_memory。"
        "当你发现用户有特定偏好（比如：不要用 var，要用 const），"
        "请调用此工具记下来，下次启动你依然会记得。"
    )
    args_schema = AddMemoryArgs
    
    async def execute(self, memory_text: str) -> str:
        manager = MemoryManager()
        manager.add_memory(memory_text)
        return f"已写入记忆：{memory_text}"
```

实际效果：
```
用户：以后写代码不要用 var，用 let 和 const
AI：（调用 AddMemoryTool）已记住：项目要求使用 let/const 而非 var
（下次启动时 AI 就知道了这个规则）
```

这个工具注册在 Registry 里，但有个坑——**循环依赖**。`AddMemoryTool` 在 `core/memory.py` 里定义，但 Registry 在 `tools/registry.py` 里初始化。如果 Registry 直接 import memory.py，而 memory.py 又 import BaseTool（在 tools/base.py 里），就形成了循环。

我的解法是用 `try/except` 延迟导入：

```python
# 在 registry.py 的最后
try:
    from mini_cc.core.memory import AddMemoryTool
    registry.register(AddMemoryTool(), aliases=["AddMemoryTool"])
except ImportError:
    pass  # 如果循环依赖导致导入失败，就不注册这个工具
```

不优雅，但能用。Python 的模块加载机制在处理循环依赖时确实不如 ES Modules 那么顺滑。

## 安全系统：三层防御

AI 能执行任意 shell 命令这件事，**比你想的危险得多**。

不是说 AI 会故意搞破坏——而是它会"产生幻觉"。比如用户说"清理一下临时文件"，AI 可能理解为"执行 `rm -rf /tmp/*`"，这在某些系统上会删掉重要的 socket 文件。

我加了三道防线：

### 第一层：破坏性命令拦截

```python
def is_destructive_command(command: str) -> bool:
    """拦截 rm -rf /、mkfs、fork bomb 等"""
    parts = re.split(r';|&&|\|\|', command)  # 拆分复合命令
    
    for part in parts:
        cmd = part.strip()
        
        # rm -rf / 的各种变体（rm -fr /, rm -r -f /, sudo rm -rf /）
        if re.search(r'\brm\s+(?:-[A-Za-z]*r[A-Za-z]*\s+-[A-Za-z]*f[A-Za-z]*'
                     r'|-[A-Za-z]*f[A-Za-z]*\s+-[A-Za-z]*r[A-Za-z]*'
                     r'|-[A-Za-z]*rf[A-Za-z]*)\s+/\*?(?:\s|$)', cmd):
            return True
        
        # mkfs（格式化磁盘）
        if re.search(r'\bmkfs\b', cmd):
            return True
        
        # fork 炸弹 :(){ :|:& };:
        if ":(){" in cmd.replace(" ", ""):
            return True
        
        # 覆写 /etc/passwd 等敏感文件
        if re.search(r'>\s*/etc/(?:passwd|shadow|fstab|sudoers)', cmd):
            return True
    
    return False
```

这里有个细节：**拆分复合命令**。如果 AI 说 `ls /tmp && rm -rf /`，你只检查整条命令会漏掉后半段。用正则 `;|&&|\|\|` 拆分后，每一段都要检查。

`rm -rf /` 的正则看起来很复杂，因为它的变体太多了：`rm -rf /`、`rm -fr /`、`rm -r -f /`、`sudo rm -rf /`、`rm -rf /*`……都得拦截。

### 第二层：子命令注入拦截

```python
def check_bash_security(command: str) -> bool:
    """拦截 $(...)、反引号等命令替换"""
    
    # 匹配 $(...) 但允许 $(pwd)、$(dirname ...)
    if re.search(r'\$\((?!\s*(?:pwd|dirname|basename))[^)]+\)', command):
        return True
    
    # 匹配反引号 `...` 同样允许安全的
    if re.search(r'`(?!\s*(?:pwd|dirname|basename))[^`]+`', command):
        return True
    
    # 拦截 zmodload（防止加载网络模块）
    if "zmodload" in command:
        return True
    
    return False
```

为什么拦截 `$(...)`？因为这是一种**命令替换**语法。如果 AI 执行 `echo $(cat /etc/passwd)`，它能把敏感文件内容输出到 stdout。

但完全禁止 `$(...)` 太严格了——`$(pwd)` 和 `$(dirname ...)` 是非常常见的安全用法，用来获取当前路径。所以我用**负向前瞻** `(?!\s*(?:pwd|dirname|basename))` 来排除这些安全命令。

### 第三层：沙箱判断

```python
SAFE_COMMANDS = {
    "ls", "cat", "echo", "pwd", "whoami", "uname", "date", "cd",
    "grep", "find", "wc", "head", "tail", "less", "more",
    "git", "node", "npm", "yarn", "python", "pip", "pytest",
    # ... 开发工具链命令白名单
}

def should_use_sandbox(command: str) -> bool:
    """判断命令是否需要放入 Docker 沙箱"""
    parts = re.split(r';|&&|\|\||\|', command)
    for part in parts:
        stripped = strip_wrappers(part.strip())  # 剥离 sudo、timeout 等包装器
        base_cmd = stripped.split()[0]
        if base_cmd not in SAFE_COMMANDS:
            return True  # 不在白名单里，需要沙箱
    return False
```

这一层的思路是：**白名单机制**。`ls`、`git`、`npm` 这些开发常用命令直接跑没问题，但 `curl`、`wget`、`ssh` 这些网络相关命令就需要沙箱隔离了。

`strip_wrappers` 函数处理一个有趣的边界情况：`sudo timeout 10 ls` 这个命令，核心命令其实是 `ls`（安全的），但前面包了 `sudo` 和 `timeout` 两个包装器。如果不剥离它们，会误判为需要沙箱。

```python
def strip_wrappers(cmd: str) -> str:
    """剥离 sudo、timeout 等包装器，提取核心命令"""
    WRAPPERS = {"timeout", "sudo", "watch", "nohup", "time", "env", "xargs"}
    parts = cmd.split()
    while parts and parts[0] in WRAPPERS:
        parts.pop(0)
        # 跳过包装器的参数（如 -u root, --signal=9, 10）
        while parts and (parts[0].startswith('-') or parts[0].isdigit()):
            parts.pop(0)
    return " ".join(parts)
```

## 一个真实的安全事件

在测试过程中，我让 AI 帮我"查看当前目录结构"。它执行了：

```bash
find . -type f -name "*.py" | head -20
```

这本身没问题。但后来它想进一步"看看某个文件的内容"，用了：

```bash
cat $(find . -name "config.py" | head -1)
```

第二层安全检查拦住了它——`$(find ...)` 不在白名单里。AI 看到"安全拦截"的错误信息后，自己改成了直接用 `FileRead` 工具来读取文件。

**这就是为什么错误信息要返回给 LLM 而不是抛异常**——它看到拦截提示后能自己调整策略。

## 记忆 + 安全的交叉问题

有个场景让我纠结过：如果 AI 通过 AddMemoryTool 记住了"用户允许执行 `rm -rf node_modules`"，下次它看到这个记忆后直接执行了 `rm -rf node_modules`——安全层要不要拦？

我的选择是：**安全层不看记忆，一视同仁**。

`rm -rf node_modules` 不会触发第一层拦截（它只拦 `rm -rf /`），但如果是 `rm -rf /`，就算记忆里写了"用户允许"，也照样拦截。安全是底线，不能被记忆覆盖。

## 小结

| 模块 | 方案 | 复杂度 |
|------|------|--------|
| 记忆持久化 | `.ai_memory/global_memory.txt` 纯文本 | 很低 |
| 记忆注入 | 拼接到 System Prompt 末尾 | 一行代码 |
| AI 主动记忆 | AddMemoryTool（一个工具） | 中等（循环依赖处理） |
| 安全第1层 | 正则拦截 `rm -rf /` 等破坏性命令 | 中等（正则复杂） |
| 安全第2层 | 拦截 `$(...)` 命令替换（允许安全的） | 低 |
| 安全第3层 | 白名单 + 沙箱判断 | 中等（包装器剥离） |
